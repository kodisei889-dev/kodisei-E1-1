1. 절대 경로 = 처음부터 끝까지 정확한 주소
어디에 있든 똑같이 찾아갈 수 있는 전체 주소예요.

예시:

“대한민국 서울시 ○○구 ○○초등학교 3층 3학년 2반”

컴퓨터 예시:
C:\Users\Min\Desktop\photo.jpg

뜻:
C드라이브부터 시작해서 Users → Min → Desktop → photo.jpg까지 가라는 뜻이에요.

✅ 특징: 지금 내가 어디에 있든 항상 같은 위치를 가리켜요.

2. 상대 경로 = 지금 있는 곳을 기준으로 찾는 길
내가 지금 있는 곳에서부터 가는 방법이에요.

예시:

“지금 교실에서 나가서 오른쪽으로 가면 음악실이 있어.”

컴퓨터 예시:

../images/cat.png

뜻:
지금 폴더에서 한 칸 위로 올라간 뒤, images 폴더 안의 cat.png를 찾으라는 뜻이에요.

✅ 특징: 내가 지금 어디에 있느냐에 따라 결과가 달라질 수 있어요.

초등학생용 한 줄 정리
절대 경로: 집 주소처럼 처음부터 끝까지 다 적은 길
상대 경로: “여기서 오른쪽, 위층으로 가”처럼 현재 위치 기준으로 적은 길
쉬운 예시 문장
“도서관을 찾는다고 해보자.”

절대 경로:

“서울시 ○○구 ○○초등학교 1층 도서관”

상대 경로:

“우리 교실에서 나와서 왼쪽으로 가면 도서관”


1. r / w / x 의 의미
기호	뜻	파일에서 의미	폴더에서 의미
r	read	파일 내용을 읽을 수 있음	폴더 안 목록을 볼 수 있음
w	write	파일 내용을 수정/삭제할 수 있음	폴더 안에 파일을 만들거나 지울 수 있음
x	execute	프로그램처럼 실행할 수 있음	폴더 안으로 들어갈 수 있음
예를 들어:

-rwxr-xr--
이런 식으로 표시됩니다.

2. 권한은 3묶음으로 나눈다
rwx r-x r--
이렇게 3개씩 끊어서 봅니다.

위치	대상
첫 번째 묶음	소유자, owner
두 번째 묶음	그룹, group
세 번째 묶음	그 외 사용자, others
예:

rwxr-xr--
은 이렇게 해석해요.

대상	권한
소유자	rwx 읽기, 쓰기, 실행 가능
그룹	r-x 읽기, 실행 가능, 쓰기는 불가
그 외	r-- 읽기만 가능

3. 숫자로 표현하는 규칙
각 권한에는 숫자가 있어요.

권한	숫자
r	4
w	2
x	1
없음 -	0
그리고 더해서 표현합니다.

예:
rwx = 4 + 2 + 1 = 7
rw- = 4 + 2 + 0 = 6
r-x = 4 + 0 + 1 = 5
r-- = 4 + 0 + 0 = 4

4. 755 해석하기
755
는 세 자리로 나눠서 봅니다.

7   5   5
소유자 그룹 그 외
각 숫자를 권한으로 바꾸면:

숫자	권한	의미
7	rwx	읽기, 쓰기, 실행 가능
5	r-x	읽기, 실행 가능
5	r-x	읽기, 실행 가능
즉,

755 = rwxr-xr-x
의미:

소유자는 모든 권한이 있고, 그룹과 다른 사용자는 읽고 실행만 가능하다.

주로 실행 파일이나 폴더에 많이 씁니다.

5. 644 해석하기
644
는 이렇게 봅니다.

6   4   4
소유자 그룹 그 외
숫자	권한	의미
6	rw-	읽기, 쓰기 가능
4	r--	읽기만 가능
4	r--	읽기만 가능
즉,

644 = rw-r--r--
의미:

소유자는 읽고 수정할 수 있고, 다른 사람들은 읽기만 가능하다.

주로 일반 문서 파일에 많이 씁니다.

한 줄 정리
r = 읽기
w = 쓰기
x = 실행
숫자는 r=4, w=2, x=1을 더해서 만든다.
755 = rwxr-xr-x
644 = rw-r--r--
예를 들어 이렇게 바꿀 수 있어요.

chmod 755 script.sh
chmod 644 memo.txt

1. 이미지(Image)란?
이미지는 프로그램을 실행하기 위해 필요한 것들을 모아 둔 실행 준비 파일 묶음이에요.

예를 들어 Python 프로그램을 실행하려면 보통 이런 것들이 필요하죠.

Python
필요한 라이브러리
내 코드
실행 설정
이걸 하나로 묶어 둔 것이 Docker 이미지입니다.

비유하면:

이미지 = 라면 봉지

라면 봉지 안에는 면, 스프, 조리법이 들어 있어요.
하지만 아직 실제 라면은 아니죠.

Docker 이미지도 마찬가지예요.
실행 준비는 되어 있지만 아직 실행 중인 프로그램은 아닙니다.

2. 컨테이너(Container)란?
컨테이너는 이미지를 바탕으로 실제로 실행된 상태예요.

비유하면:

컨테이너 = 끓인 라면

라면 봉지를 뜯고 물을 넣어 끓이면 실제로 먹을 수 있는 라면이 되죠.
이미지를 실행하면 실제로 작동하는 컨테이너가 됩니다.

포트 매핑은 “교실로 가는 안내 문”이야
Docker 컨테이너를 학교 안의 특별한 교실이라고 생각해볼게요.

그 교실 안에는 웹사이트를 보여주는 친구가 있어요.

컨테이너 = 특별한 교실
웹 서버 = 교실 안에 있는 친구
그런데 이 교실은 문이 잠겨 있고, 밖에서는 바로 들어갈 수 없어요.

그래서 안내 문을 만들어야 해
밖에 있는 사람이 교실 안 친구에게 말을 걸려면
학교 입구에 이렇게 안내판을 붙여야 해요.

학교 입구 8080번 문으로 들어오면
특별 교실 5000번 문으로 보내주세요!
Docker 명령어로는 이렇게 써요.

docker run -p 8080:5000 my-app
뜻은:

내 컴퓨터 8080번 문 → 컨테이너 안 5000번 문
으로 연결한다는 뜻이에요.

브라우저에서 접속하면?
내 컴퓨터에서 이렇게 들어가요.

http://localhost:8080
그러면 Docker가 이렇게 안내해줘요.

아! 8080번 문으로 왔네?
그럼 컨테이너 안 5000번 문으로 보내줄게!
한 줄로 쉽게 말하면
포트 매핑은 내 컴퓨터에서 컨테이너 안 프로그램으로 들어가는 길을 만들어주는 거야.

즉,

내 컴퓨터 문 번호와
컨테이너 문 번호를 연결하는 것

1. 컨테이너 데이터는 기본적으로 사라질 수 있음
Docker 컨테이너는 실행했다가 지울 수 있는 환경이에요.

예를 들어 컨테이너 안에서 파일을 만들었다고 해볼게요.

컨테이너 안에 data.txt 생성
그런데 컨테이너를 삭제하면?

docker rm my-container
컨테이너 안에 있던 파일도 같이 사라질 수 있어요.

즉,

컨테이너 내부 데이터는 컨테이너 생명주기와 함께 사라질 수 있습니다.

2. 그래서 볼륨이 필요함
볼륨은 컨테이너 밖에 데이터를 저장하는 공간입니다.

컨테이너 안 프로그램
        ↓
Docker 볼륨에 데이터 저장
        ↓
컨테이너를 지워도 데이터는 남음
즉, 볼륨은:

컨테이너가 삭제되어도 데이터를 유지하기 위한 저장 공간

입니다.

3. 쉬운 비유
컨테이너를 임시 교실이라고 생각해볼게요.

교실 안 책상에 공책을 두면, 교실을 치울 때 공책도 사라질 수 있어요.

하지만 공책을 개인 사물함에 넣어두면?

교실이 바뀌어도 공책은 사물함에 남아 있음
여기서:

컨테이너 = 임시 교실
볼륨 = 개인 사물함
데이터 = 공책
입니다.

4. 볼륨 사용 예시
볼륨을 만들고:

docker volume create my-data
컨테이너에 연결해서 실행합니다.

docker run -v my-data:/app/data my-app
뜻은:

Docker 볼륨 my-data를
컨테이너 안 /app/data 폴더와 연결한다
이제 컨테이너 안에서 /app/data에 저장한 파일은
컨테이너를 삭제해도 my-data 볼륨에 남아 있습니다.

5. 예시 상황
데이터베이스 컨테이너를 생각해봅시다.

docker run -v db-data:/var/lib/mysql mysql
이렇게 하면 MySQL 데이터가 볼륨에 저장됩니다.

그래서 MySQL 컨테이너를 지웠다가 다시 만들어도
같은 볼륨을 연결하면 기존 데이터를 다시 사용할 수 있습니다.

6. 정리
Docker 볼륨이 필요한 이유는:

컨테이너는 삭제되면 내부 데이터가 사라질 수 있음
중요한 데이터는 컨테이너 밖에 저장해야 함
볼륨을 사용하면 컨테이너를 삭제해도 데이터가 유지됨
데이터베이스, 업로드 파일, 로그 저장 등에 자주 사용됨
한 줄로 말하면:

Docker 볼륨은 컨테이너가 사라져도 데이터를 남겨두기 위한 저장 공간입니다.

git = 공책에 글 적기 = 집 = 한정된 공간
github = 공책에 적은 글을 온라인에 올리기 = SNS = 나를 알게된 사람들이 모두 알 수 있음.
